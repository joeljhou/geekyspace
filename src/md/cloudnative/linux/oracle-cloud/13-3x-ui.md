# 安装 3X-UI 面板指南

> [!WARNING] 合规与风险提示
> 3x-ui / Xray 属双用途工具，可能违反部分国家或地区法规及上游服务条款。仅作个人学习研究与自用，遵守所在地法律法规，请勿用于商业转售或对外公开售卖。因节点端口暴露、流量特征等产生的安全与合规风险自负。

## 一、安装
### 1. 执行一键安装脚本
```bash
bash <(curl -Ls https://raw.githubusercontent.com/mhsanaei/3x-ui/master/install.sh)
```

> [!TIP] 架构自动识别
> 脚本通过 `uname -m` 判断架构。本机输出 `Arch: arm64`，对应下载 `x-ui-linux-arm64.tar.gz`，并自带 `xray-linux-arm64`、`mtg-linux-arm64` 以及 `geoip/geosite` 数据文件，无需手动处理 ARM 兼容性。
### 2. 交互式执行

1. **数据库选择（Database Selection）**
	- 500人以内选择 `SQLite` 即可![image.png](http://img.geekyspace.cn/pictures/2026/202608031757808.png)
2. **面板端口设置（Panel Port）**
	- 直接回车生成随机端口 
	- 推荐管理面板端口：`2196`，因为订阅服务默认端口：`2096`![image.png](http://img.geekyspace.cn/pictures/2026/202608031758214.png)
3. **SSL 证书设置（SSL Certificate Setup）**
	- 这里选择 `4`，因为面板将通过 `Cloudflare Tunnel` 提供 HTTPS，3x-ui 本身无需再单独配置 SSL。![image.png](http://img.geekyspace.cn/pictures/2026/202608031801394.png)
4. **面板监听地址（Bind Address）**
	- 绑定到 `127.0.0.1`
	- 浏览器中打开：`http://localhost:57913/7hn6rMhzsX2W1c9Adn/`![image.png](http://img.geekyspace.cn/pictures/2026/202608031816684.png)
5. **随后自动操作**
	- 无需交互，脚本自行完成![`image.png`](http://img.geekyspace.cn/pictures/2026/202608031852257.png)
### 3. 安装后设置
**确认是否安装成功**
```shell
sudo systemctl is-active x-ui
sudo systemctl is-active cloudflared
sudo ss -lntp | grep ':2196'
curl -i http://127.0.0.1:2196/joeljhou/
```

```shell
# 查看当前监听端口、WebBasePath 与用户名密码等
x-ui settings

# 修改访问后缀
sudo /usr/local/x-ui/x-ui setting -webBasePath "joeljhou"
# 修改用户名和密码（非交互式，一行命令）
sudo /usr/local/x-ui/x-ui setting -username <新用户名> -password <新密码>
# 执行后重启生效
sudo systemctl restart x-ui
```

> [!TIP] 备份与恢复
> 脚本版的所有配置（账号、入站、客户端、流量统计）都在单文件 `/etc/x-ui/x-ui.db`。
## 二、网络设置

本节只配置 3x-ui 管理后台、订阅服务和美国 Reality 节点。最终验证结果：小火箭可以通过订阅二维码成功导入 `us1-reality` 节点。

### 1. 网络结构与域名分工

| 域名                      | 用途                  | Cloudflare 设置     | 实际目标                       |
| ----------------------- | ------------------- | ----------------- | -------------------------- |
| `vpn.geekyspace.cn`     | 3x-ui 管理后台          | Cloudflare Tunnel | `http://127.0.0.1:2196`    |
| `vpnsub.geekyspace.cn`  | 小火箭订阅服务             | Cloudflare Tunnel | `http://127.0.0.1:2096`    |
| `vpn-us1.geekyspace.cn` | 美国 VLESS Reality 节点 | A 记录、DNS only     | Oracle 公网 IP 的 `TCP 51820` |

三条链路不要混用：

```text
浏览器管理后台
https://vpn.geekyspace.cn/joeljhou/
    → Cloudflare Tunnel
    → 127.0.0.1:2196

小火箭获取订阅
https://vpn-sub.geekyspace.cn/sub/<客户端 Sub ID>
    → Cloudflare Tunnel
    → 127.0.0.1:2096

小火箭连接节点
vpn-us1.geekyspace.cn:51820
    → DNS-only A 记录
    → Oracle 公网 IP:51820/TCP
    → Xray VLESS Reality 入站
```

> [!IMPORTANT] 节点不走 Cloudflare Tunnel
> Cloudflare Tunnel 用于管理后台和 HTTP 订阅服务。`VLESS + RAW/TCP + Reality` 节点需要直连 Oracle 公网 IP，因此 `vpn-us1.geekyspace.cn` 必须使用灰色云朵的 `DNS only`。

### 3. 创建 VLESS Reality 入站

进入“入站 → 添加入站”，或者编辑现有的 `us1-reality`。
#### 3.1 基础配置

![VLESS 入站的自定义分享地址与端口](http://img.geekyspace.cn/pictures/2026/202608032355578.png)

“地址”和“自定义分享地址”作用不同：

- “地址”决定 Xray 在服务器上监听哪个网卡；留空表示监听所有网卡。
- “自定义分享地址”决定二维码和订阅链接中写入哪个节点域名。这里必须是 `vpn-us1.geekyspace.cn`。

#### 3.2 协议和传输

![协议](http://img.geekyspace.cn/pictures/2026/202608040000283.png)

VLESS 自身的“加密 `none`”不等于最终连接不加密；实际安全层由下一步的 Reality 提供。

![image.png](http://img.geekyspace.cn/pictures/2026/202608040003695.png)

#### 3.3 Reality 安全配置

进入“安全”标签页，选择 `Reality`：

![image.png](http://img.geekyspace.cn/pictures/2026/202608040010494.png)


> [!NOTE] “获取新证书”不是申请 HTTPS 证书
> 这个按钮实际生成 Reality 使用的 X25519 公私钥对，不是 Let’s Encrypt 或 Cloudflare 域名证书。Reality 不要求给 `vpn-us1.geekyspace.cn` 申请传统 SSL 证书。

不要选择“安全 → 无”。选择“无”后生成的链接会带有 `security=none`，公网 VLESS TCP 没有 Reality 安全层和伪装。本次无法连接的一个关键原因，就是入站备注虽然叫 `us1-reality`，实际安全设置却是“无”。

完成后点击“保存更改”。入站列表应显示：

![入站列表中已启用的 VLESS TCP Reality 节点](http://img.geekyspace.cn/pictures/2026/202608040011799.png)

### 4. 配置订阅服务

在“面板设置 → 订阅设置 → 常规”中填写：

![订阅服务监听地址与反向代理 URI](http://img.geekyspace.cn/pictures/2026/202608040025626.png)

“反向代理 URI”必须填写完整的外部 HTTPS 基址，并且以 `/` 结尾。它决定 3x-ui 在二维码中显示什么订阅地址。

> [!TIP] 随机订阅路径
> 3x-ui 会提示默认 `/sub/` 路径已知。需要进一步隐藏路径时，可以把“URI 路径”和“反向代理 URI”中的 `/sub/` 同时改成相同的随机路径；不要只改其中一个。

### 5. 创建美国节点 DNS 记录

进入 `Cloudflare → geekyspace.cn → DNS → Records → Add record`：

![image.png](http://img.geekyspace.cn/pictures/2026/202608040030004.png)

不要把 `vpn-us1.geekyspace.cn` 添加到 Tunnel，也不要打开橙色云朵。普通 Cloudflare HTTP 代理不能代替 Reality 原始 TCP 节点入口。

检查解析结果：

```bash
dig +short vpn-us1.geekyspace.cn
```

输出应当是 Oracle 服务器的公网 IPv4。


## 三、端口放行
### 1. Oracle 安全列表（VCN）

**新增规则：**
![image.png](http://img.geekyspace.cn/pictures/2026/202608040036401.png)

Oracle Security List/NSG 是云平台外层防火墙。这里只需要公开真实节点端口 `51820/TCP`；管理端口 `2196` 和订阅端口 `2096` 通过 Tunnel 访问，不应直接暴露公网。

### 2. Ubuntu 防火墙
```bash
# 先确认 Xray 已经实际监听
sudo ss -lntp | grep ':51820'
# 预期
LISTEN ... 0.0.0.0:51820 ... xray
```

如果 UFW 已启用，再放行 TCP：
```bash
sudo ufw status
sudo ufw allow 51820/tcp comment '3x-ui VLESS Reality us1'
sudo ufw status
```

> [!IMPORTANT] 每个入站端口都要单独放行
> 如果再创建 `us2-reality:51821`，Xray 监听 `51821` 并不会自动放行防火墙。还必须同时配置 Ubuntu UFW 的 `51821/TCP`、Oracle Security List/NSG 的 `51821/TCP`，以及该入站对应的自定义分享域名。缺少任意一项，该节点仍会超时。
